# 0.3.0rc1 Release Candidate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a reviewed GraphRAG C9 `0.3.0rc1` candidate as protected Git tag
`v0.3.0-rc.1` and a GitHub prerelease without publishing to a package index.

**Architecture:** Prepare release metadata on a dedicated branch, prove it with a focused
governance contract and the existing local gate, then merge it through a release pull request.
Only after the checked pull request is merged will the workflow tag the resulting `main` commit
and create the GitHub prerelease.

**Tech Stack:** Python 3.11, TOML, Markdown, pytest, Python build, Git, GitHub Actions, GitHub
connector, and the authenticated GitHub web interface.

## Global Constraints

- Python must remain `>=3.11,<3.12`; execute release checks with Python 3.11.
- Python package version is exactly `0.3.0rc1`.
- Git tag is exactly `v0.3.0-rc.1`.
- Release branch is exactly `codex/release-0.3.0rc1`, targeting `main`.
- Do not rewrite or squash the 52 candidate commits.
- Do not modify runtime behavior, dependency versions, `requirements.txt`, or
  `requirements-dev.txt`.
- Do not publish to PyPI or any other package index.
- Do not commit `dist/`, build directories, test caches, or gate reports.
- Do not create or move the tag until the release pull request is merged and all required checks
  pass.
- If a same-name tag exists, a required check fails, or tag protection is absent, stop without
  creating or replacing the tag.
